# Prompt for Claude

Use citation.inator to update the references on this website. Work in the website checkout and clone citation.inator separately for its compiler, examples, and documentation.

1. Clone `https://github.com/randal-cox/citation.inator.git`. In that checkout, use Node.js 22 or later and run `npm ci`, `npm run build`, and `npm test`. Read [README.md](../README.md) and [the integration guide](integration.md). Record the library commit you use so the integration can be reproduced.
2. Inspect the website’s authoring files and build commands. Find the in-text citations, bibliography, and endnotes before changing them. For each reference you migrate or move, preserve the intended work and the claim it supports. Reuse verified identifiers and metadata. Flag uncertain matches or missing records for review.
3. Integrate one representative page first. In editable prose, use directives such as `{citation doi:10.1017/S0003055419000534}` and put `{citation endnote}` on its own paragraph where you want the bibliography. For HTML or Markdown sites, keep the existing page structure. Run `npm pack` in the library checkout and install that tarball in the website checkout before importing `compileHTML` or `compileMarkdown` from `citation-inator/markup`. A Python build can send HTML or paragraph batches to `node /path/to/citation.inator/scripts/compile.mjs --json` using the separate checkout. Set `citationStyle: "chicago-author-date"` and `endnotesHeading: "References"` where those match the page. Use `prefix` and `locator` for “see also” and page references, and let the compiler assign year suffixes. Give each fragment that shares a page a unique namespace. Use the same approach for the remaining references in scope after the first page works.
4. Generate each fragment and its matching JSON from the source prose and cache. Copy `dist/citation-inspector.mjs` and its adjacent `dist/citation-inspector.css` to the website’s public assets, then load the stylesheet with a link and the module with a script of type `module` in the site template. Insert the fragment inside `<citation-inspector data-cache="…">` and point the attribute at the generated JSON on the same origin. Preserve verified access destinations as `library` or `full-text` locations, feed the site’s reader settings into `accessProviders`, and retain editorial italics via `citationParts` where needed. Keep the source and cache in the website’s authoring workflow so the next edit can be regenerated.
5. Run the website’s build and preview the affected pages over HTTP. Check that the citations still point to the intended works, that the endnotes and return links reach the right places, and that the inspector opens by click and keyboard. Check one narrow viewport, the **Move panel** command, and the page with JavaScript disabled. Check the browser console and network panel for missing assets. Summarize the pages changed, references that still need review, and the checks you actually ran.
