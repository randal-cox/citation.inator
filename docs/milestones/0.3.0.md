# Milestone 0.3.0 — Reviewed citation import

**In progress. No preview or final release yet.** The maintainer selected 0.3.0 for F4 once confidence is established. Current package metadata and released assets remain 0.2.0. Development is isolated on `codex/citation-import`.

## Agreed scope and active tracks

The maintainer confirmed on 20 November 2026 that this milestone owns reviewed import and the smaller outstanding reader/integration/documentation fixes. All five import tracks are authorized to proceed without waiting for the host editor repository:

1. Broaden recognition and local matching, including numeric citations and uncertain author-date forms. Initial numeric bracket proposals now use explicit document-local reference labels.
2. Develop and measure rule-based reference parsing, preserving unsupported entries as raw text. Field parsing remains pending.
3. Extend extraction across markup and document formats while retaining source provenance and existing embedded bibliography-manager metadata. Native adapters remain pending.
4. Develop explicit review decisions and revision-bound edit plans. Coordinate editor application behavior with the host when ready; acceptance/edit APIs remain pending.
5. Build independently checked and held-out measurements for each stage. Current developer-labelled corpus results are not held-out evaluation.

Smaller tasks included in this milestone:

- [ ] Show unknown-profile access help once per reading list, retaining inspector settings access.
- [ ] Document a stable host hook before reference items.
- [ ] Create the comprehensive citation-style catalogue and current support matrix.
- [ ] Extend host integration regression coverage.
- [ ] Perform native Safari, VoiceOver and physical-phone scenarios; record pending/unavailable checks honestly.

Installed APIs/CLI, browser tools, demos, guides, packaging, independent milestone reviews and adopter acceptance remain release requirements. External bibliography-manager ingestion/connectors, broken-link review and related source maintenance are deferred to [0.4.0](0.4.0.md). Preserving metadata already embedded in an imported document stays in 0.3.0.

## Delivered

- Initial source-only, offline APA/Chicago author-date detection and matching prototype, with review-required results and original source ranges.
- Initial bracket-numeric detection with bounded range expansion and explicit document-local `referenceNumber` matching; duplicate labels stay ambiguous and unlabelled cache order supplies no identity.
- Synthetic regressions for grouped citations, basic locators/prefixes, Unicode offsets, byline ambiguity, year letters, reprints, existing notation and narrative boundaries.
- A local paired-format intake audit and an ignored/private corpus workspace. No author-supplied unpublished document or extract is committed.
- Initial text/HTML/Markdown extraction with fragmented source provenance, citation-link labels, protected regions and explicit conservative mapping limits.
- Explicit source-only Crossref bibliographic search with ranked review candidates, comparisons, bounded requests, validated search caching and retained failure evidence.
- Developer-checked private citation/reference labels and cross-format matching comparisons.
- [Development/corpus protocol](../import-development.md) describing the extraction/matching boundary, expected answers, held-out evaluation and remaining work.

These are development foundations, not a finished import feature or supported 0.2.0 export.

## Acceptance and evidence

The initial implementation passes 111 unit tests on Node 22.23.3, including 43 source-only import tests. Independent experimental review identified narrative and byline-completeness errors; regression tests were added and uncertainty is retained rather than allowing false unique results. Narrative comma-list alternatives still need further constraint before public exposure.

The private corpus shows matching detector-item fields across four visible-text representations of one manuscript. That is a consistency observation, not a citation-to-reference accuracy score. Developer-checked text spans now account for 25 cited items: 21 matching bibliography entries and four expected missing entries. The same labels transfer consistently across four text views and direct Markdown extraction with original source fragments. Markdown diagnostics identify skipped regions; this does not establish whole-document preservation or broad format coverage. Independent curator review and held-out measurement are pending. The public PDF sample provides an additional numeric-citation case, now exercised by an initial numeric prototype. A mechanical reference-heading inventory also finds a duplicate label caused by a wrapped page number; matching retains ambiguity rather than silently choosing an entry. This is a development inventory, not checked numeric accuracy.

**Earlier HTML extraction testing verdict: PASS for experimental development check-in.** Independent review found control-boundary, closed native visibility and redundant link-role issues; all were fixed with regressions. The reviewer independently reran 84 tests and probed source maps, entities and malformed HTML. This verdict does not approve a public API or milestone release.

**Current Markdown/search testing verdict: PASS for experimental development check-in.** The independent reviewer ran all 107 tests on Node 22.23.3 and adversarial mock-provider probes. Findings about entity rendering, URL labels, heading offsets, transformed/escaped notation, invalid cache envelopes and DOI-only cache consistency were fixed with regressions and rechecked. No remaining findings in that bounded scope; public API/release approval remains pending. The reviewer did not access private corpus data or repeat live searches.

**Numeric matching verdict: PASS for experimental development check-in.** The independent reviewer ran all 111 tests and checked expansion limits, offsets, custom notation, explicit label mapping and malformed nested/incomplete bracket groups. Inner numeric islands are not imported from malformed containers. Linked numeric Markdown remains partially supported; no public API or release approval is implied.

The HTML adapter has synthetic regression evidence and one development case rendered locally from Markdown (matching the same 25 item labels); it conservatively maps decoded text to whole source text nodes and does not evaluate CSS visibility. Two live public-reference checks returned HTTP 200: title search retrieved the expected DOI first, while DOI-as-bibliographic-text search returned conflicts. Neither establishes general retrieval accuracy. No private manuscript was sent. No native-document adapter, browser, package-consumer or adopter acceptance is claimed for F4. No 0.3.0 version bump, release tag or publication has occurred.

## Known limits and follow-up

- Expand developer labels with independent checks and hold back evaluation material before reporting accuracy.
- Broaden the in-text matcher and integrate reviewable Crossref search into the installed API and review workflow, as requested by the adopter.
- Expand conservative Markdown coverage and add native file extraction adapters with source maps. Preserve editable Zotero metadata when available; opaque hyperlinks alone are insufficient.
- Broaden author/date/locator coverage, numeric citation mapping and reference-parsing rules through measured corpus cases.
- Keep unknown, ambiguous and unsupported material intact; require explicit acceptance before producing source/cache edits.
- Retain a fully local path. Any later AI parser is an optional fallback, not an import dependency.
- Complete API, packaging, documentation, UX and scholarly-integrity adversarial reviews before sharing a preview; run the full milestone procedure before release.
