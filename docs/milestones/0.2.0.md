# Milestone 0.2.0 — Article tooling

**Candidate implemented and independently reviewed: 0.2.0-preview.0. Awaiting adopter acceptance; final release is pending.**

This milestone implements the 20 November editor/bibliography requests F1–F3. F4 is retained as a reviewed-import plan. Candidate work is isolated on `codex/article-tooling`; stable `v0.1.4` and its published artifacts are unchanged.

## Delivered

- F3: explicit per-item editor-only `note:` metadata; structured `describeCitation` and source-preserving `annotateMarkers` queries; JSON CLI description, annotation and stale-note checks; a separate browser tools bundle.
- F1: emitted local occurrence inventories, a portable site-index helper, compiler-supplied cross-page return links, contextual accessible names, structured binding metadata and inspector site-use sections. Static links remain usable without JavaScript.
- F2: curated record tags, same-origin masked icons with visible names, per-list role overrides, optional inline tags, build-time any/all selection and independent keyboard-operated browser filters with live counts.
- Multi-page article/bibliography examples and an offline editor tool in both demo distributions. README, Guide and integration documentation cover the new contracts and their limits.

## Acceptance and evidence

The final `npm run milestone:check` passed on 20 November using Node 22.23.3 and Chrome 158.0.8127.36: **63 unit tests**, the build, the full browser suite and working-tree consistency checks. Twelve focused unit tests cover F1–F3. The browser checks include copied standalone files under CSP, actual multi-page targets, no-JavaScript returns, keyboard/filter counts, isolated lists, custom class prefixes, narrow dark/forced-colour presentation and the self-contained editor bundle. Light and dark screenshots were visually inspected. Provider outage/race checks use controlled responses, not a fresh live-provider acceptance run.

An independent source/API review found and verified repairs for generated-note markup injection, multiline metadata, HTML eligibility differences, relative-path deduplication, filtered year letters and missing-ID diagnostics. Copy/rebase probes also verified tag-mask IDs and local site-use metadata.

## Known limits and follow-up

- F4 formatted-reference parsing and reviewed import are planned, not implemented. See the [article-tooling plan](../article-tooling-plan.md#f4-reviewed-import-delivered-in-smaller-stages).
- Annotation operates on literal brace notation. Encoded notation is left intact with a diagnostic; Markdown regions that cannot be located exactly are conservatively skipped and reported.
- Source-only notes are editor aids, not confidential comments. A group containing an unresolved work is left unchanged for review.
- Hosts own published-page discovery, routes, stable passage identifiers and draft exclusion. Relative URLs must suit each page's base path; the index helper does not rewrite routes.
- Browser filters start with English UI wording. They do not yet share the reader-access translation catalogue.
- A source's tags and a particular article's use of it remain distinct through explicit per-list overrides. The existing host hook remains available; arbitrary HTML insertion is outside this change.
- Native Safari, VoiceOver and physical-phone verification remains open. Browser emulation and automated accessibility checks are narrower evidence.
- Earlier follow-ups, including repeated unknown-profile help and the full citation-style catalogue, remain in the [roadmap](../../ROADMAP.md).
