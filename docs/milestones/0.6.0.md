# Milestone 0.6.0 — Connected bibliographies and source maintenance

**Planned. No implementation, preview or release claimed.** The maintainer assigned this logically separate scope on 20 November 2026. Reviewed import is released as 0.4.0; developer learning/live demos shipped as 0.5.0, and the 0.5.1 candidate remains under maintainer/adopter review.

## Agreed scope

- Ingest bibliography-manager interchange files, initially BibTeX, RIS and CSL-JSON.
- Explore explicit, read-only connections to Zotero and other managers for selected items or collections.
- Preserve identifiers, provenance, edition distinctions and local edits; review proposed reimport changes rather than replacing records silently.
- Review broken or stale source links, keeping failed checks distinct from evidence that a work is unavailable.
- Improve sourced correction, retraction and expression-of-concern notices. Verify that the notice applies to the cited work and retain the original citation and editorial decision.
- Reuse the reviewed-import records and decision model instead of creating a second identity system.

Embedded Zotero metadata encountered during article extraction remains a 0.4.0 preservation concern. External collections, manager services and ongoing source upkeep belong here.

## Writer-first planning discussion — 25 November 2026

The maintainer's personal priority is to keep using Zotero and rapidly insert a work from the current library into a cite marker. Proposed acceptance workflow: invoke Cite in draft, search the connected Zotero library or an imported collection, choose work(s) and locators, and atomically insert canonical markers plus the selected bibliographic snapshot. The article remains renderable when Zotero is closed. This is a planning priority, not implementation authorization or a silently narrowed release scope.

Proposed ownership: cite handles format adapters, identifier/edition reconciliation, portable records, provenance, reviewed refresh and bibliography serialization. Draft handles the picker, keyboard/cursor interaction, site connection settings, secure credential persistence and atomic source/record edits. A reusable local connector adapter may belong to cite; its transport/permission owner must be settled with draft before implementation.

Evaluate an explicit read-only Zotero local API connection for local clients, and the authenticated Web API for hosted workflows. Test browser-origin/private-network behavior before choosing direct browser access versus a local bridge. Treat Zotero's own HTTP citing-dialog protocol as a separate feasibility option, not a prerequisite for a simple library picker. No local library has been accessed during this planning discussion.

Add downloadable cited-work bibliographies in CSL-JSON, BibTeX and RIS, with visible Playground examples and actual Zotero import round trips. File export is distinct from updating an existing Zotero item or synchronizing a library; bidirectional writes are not part of the currently agreed read-only connector exploration. Preserve stable source item identity and version provenance alongside DOI/ISBN, without exposing private library data in published pages.

Sources: [Zotero local API](https://www.zotero.org/support/dev/web_api/v3/local_api), [Web API](https://www.zotero.org/support/dev/web_api/v3/basics), [HTTP citing protocol](https://www.zotero.org/support/dev/client_coding/http_integration_protocol), [Zotero import formats](https://www.zotero.org/support/kb/importing_standardized_formats).

## Maintainer preferences recorded 25 November 2026

- A web-based draft citation picker is attractive; avoid requiring the cumbersome local Zotero dialog workflow experienced in Google Docs. Prefer a smooth in-editor search/insert experience while continuing to maintain the library in Zotero.
- Explore a hybrid connector: Web API for hosted/synced library use, optional local Zotero access when useful. Neither path is selected yet. Use one bibliographic identity/merge model; do not assume local and web version counters are interchangeable. Test permissions, origin behavior, disconnected/unsynced states and duplicate identity before choosing transport/failover. No automatic bidirectional sync is agreed.
- Prioritize Already cited, respecting Zotero curation through a reviewed merge, Open in Zotero, quote-plus-locator capture, relevant update review and per-manuscript bibliography export. Keep Zotero base metadata and document-specific assertions distinguishable so neither silently overwrites the other.
- cite owns the reusable CSL-JSON/BibTeX/RIS serializers and its own Playground downloads. Draft supplies appropriate editor download controls and calls those APIs; it should not duplicate exporters. File downloads are not the same as updating existing Zotero records.
- Evaluate other managers for future interoperability, but direct connectors to multiple managers are not a target for this release. Standard interchange-file support remains in the existing 0.6.0 scope.
