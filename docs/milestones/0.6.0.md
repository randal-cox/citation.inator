# Milestone 0.6.0 — Connected bibliographies and source maintenance

**In development; writer workspace and reusable library preview, no final release or authenticated connected-editor acceptance.** Randal authorized starting 0.6 on 25 November, then requested and completed a detailed plan/fresh-agent discussion. He endorsed the modest loop, accepted saved-work offline scope and authorized bounded connection experiments with his running Zotero/BEST library. Version 0.5.1 is released and adopted by draft. The [reviewed Zotero plan](../plans/zotero-integration.md) is the current design proposal, not a shipped integration or final 0.6 scope change.

## Agreed scope

- Ingest bibliography-manager interchange files, initially BibTeX, RIS and CSL-JSON.
- Explore explicit, read-only connections to Zotero and other managers for selected items or collections.
- Preserve identifiers, provenance, edition distinctions and local edits; review proposed reimport changes rather than replacing records silently.
- Review broken or stale source links, keeping failed checks distinct from evidence that a work is unavailable.
- Improve sourced correction, retraction and expression-of-concern notices. Verify that the notice applies to the cited work and retain the original citation and editorial decision.
- Reuse the reviewed-import records and decision model instead of creating a second identity system.

Embedded Zotero metadata encountered during article extraction remains a 0.4.0 preservation concern. External collections, manager services and ongoing source upkeep belong here.

## Maintainer preferences recorded 25 November 2026

- A web-based draft citation picker is attractive; avoid requiring the cumbersome local Zotero dialog workflow experienced in Google Docs. Prefer a smooth in-editor search/insert experience while continuing to maintain the library in Zotero.
- Explore a hybrid connector: Web API for hosted/synced library use, optional local Zotero access when useful. Neither path is selected yet. Use one bibliographic identity/merge model; do not assume local and web version counters are interchangeable. Test permissions, origin behavior, disconnected/unsynced states and duplicate identity before choosing transport/failover. No automatic bidirectional sync is agreed.
- Prioritize Already cited, respecting Zotero curation through a reviewed merge, Open in Zotero, quote-plus-locator capture, relevant update review and per-manuscript bibliography export. Keep Zotero base metadata and document-specific assertions distinguishable so neither silently overwrites the other.
- cite owns the reusable CSL-JSON/BibTeX/RIS serializers and its own Playground downloads. Draft supplies appropriate editor download controls and calls those APIs; it should not duplicate exporters. File downloads are not the same as updating existing Zotero records.
- Evaluate other managers for future interoperability, but direct connectors to multiple managers are not a target for this release. Standard interchange-file support remains in the existing 0.6.0 scope.
