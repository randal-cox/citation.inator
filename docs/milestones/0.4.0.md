# Milestone 0.4.0 — Reviewed citation import

**In development. No preview or final release.** On 21 November 2026 the maintainer moved the large import scope out of 0.3.0, allowing draft.inator to adopt a stable integration release first. Work is preserved on `codex/citation-import`. Developer learning follows in [0.5.0](0.5.0.md), then bibliography connections in [0.6.0](0.6.0.md).

## Agreed scope and active tracks

1. Recognize and match citation forms, retaining ambiguity and unknowns.
2. Parse reference fields with measured algorithmic rules; retain raw/unsupported entries.
3. Extract pasted text/HTML/Markdown and native documents with source mapping and existing citation metadata preserved.
4. Review identities and text spans separately, then propose revision/context-bound edits with explicit acceptance.
5. Measure extraction, recognition, field parsing, matching and provider retrieval separately with fresh independent cases.

Import includes the document-first review interface, with the bibliography visible and choices attached to highlighted in-text citations. The editor owns decorations, editor-position mapping, transactions, undo and publishing. Stable classifier/note/prefix/reader-help additions belong to 0.3.0, not to this scope.

## Existing prototype

- APA/Chicago author-date, numeric brackets/ranges and conservative undated recognition/matching against supplied records. Explicit document-local numbers, source suffixes and reprint dates remain distinct.
- Text/HTML/Markdown extraction with source fragments, protected regions, conservative decoded mappings and explicit skipped-region diagnostics.
- Partial reference-field rules and opt-in review-required Crossref bibliographic search, with raw evidence, conflicts, bounded requests and no automatic record mutation.
- Node review/edit protocol binding source/proposals; local demo additionally binds complete records/style context. Uncertain spans and linked/noncontiguous source stay pending an adapter.
- A local full-source text/Markdown demo deriving bibliography records from Raw Document, with adjustable boundaries, live edits, UTF-8 file selection/drop, original downloads and portable Markdown/cache output. Import Document and Resolve Citations headings separate source choice from review; the selector distinguishes dropped/chosen files. The Avery example remains ambiguous without a reader choice.
- Subdued green selected targets, muted red citations needing review and gray citations explicitly left unchanged. Unique candidates are preselected; a whole group is automatically selected only when every item is unique without an uncertain author span. The demo policy does not change the core matcher’s review-required evidence or verify identity.
- Immediate suggested-target radio choices and a Don’t fix radio (no second confirmation), Previous/Next navigation between red citations, Up/Down radio selection, Left/Right red-citation navigation even from radios, preserved text caret keys and stronger red highlighting.
- A real-publication lookup-development example with identifiers withheld and a separate publisher-checked DOI answer key; original and correction identities stay distinct. This is not a search benchmark or runtime lookup implementation.
- Compact suggested-target radio choices, explicit manual DOI/ISBN/URL overrides without metadata lookup, a Don’t fix action and a collapsed supplied bibliography. Manual targets retain the same source/span guards.
- Example selection loads automatically; format overrides immediately reanalyze, and raw/reference edits reanalyze after a typing pause. There is no separate Analyze button. Detected format uses conservative source-shape inference among the three supported modes, with mixed/narrative-only uncertainty requiring a manual choice. The color key shares document tints and includes the reserved orange completion state.
- Converted Document remains open and refreshes on citation choices, preserving popup focus and ignoring stale responses. Export actions are disabled while the changed output is pending.
- The interface removes development narration and repeated instructions; a Converted Document disclosure generates the result on opening, with optional technical evidence grouped under Diagnostics.
- The primary result is full-width raw Markdown with literal `{cite …}` markers and an exact `.md` download. Rendered reading output is a collapsed optional check. Local-ID markers require the downloadable reference cache.
- Candidate/group decisions (including the demo’s automatic unique-match policy), retained unresolved/rejected text, downloadable preview copies, stale controls/evidence invalidation and partial-numeric preview safeguards.

These are development foundations, not an installed import API or native-file import promise. The demo requires `npm start`; it is not a static ZIP service.

## Known limits and follow-up

The detached source/reference modeling gap is fixed in the text/Markdown development path. All default examples and UTF-8 TXT/Markdown imports derive records from their editable bibliography. Source edits conservatively clear prior decisions. Partial rules retain unknown fields and raw references; unsupported native files are rejected. PDF/native adapters, enrichment and browser-native distribution remain unfinished.

The [browser enrichment plan](../import-enrichment-plan.md) now specifies the proposed work-selection/completion state model, provider/privacy boundaries, strict automatic matching, edition-aware ISBN discovery and failure/manual paths. One HTTP metadata probe per provider observed CORS headers; actual browser enrichment is not implemented or verified. Independent API/testing plan review passed with explicit in-flight invalidation, edition-safe coalescing and versioned automatic-match criteria added to the acceptance requirements. The maintainer explicitly affirmed that a reference must be finishable without inventing an identifier. Current demo green still means selected for conversion, not the future ready/completed state.

- Native DOCX/ODT/PDF adapters and live bibliography-manager metadata preservation remain unfinished.
- Expand conservative Markdown coverage and explicit source-span review; do not erase markup or leave generated markers stranded in existing links.
- Build browser-native/installed APIs and CLI equivalents, with a real host integration and fresh evaluation before sharing a release candidate.
- Preserve exact identities, editions, source letters, prefixes and locators; unknown fields remain unknown.
- Keep local parsing/review usable without AI or providers. Any external lookup or optional parser is explicitly invoked.
- Complete milestone packaging, documentation, independent reviews and adopter checks. Native Safari, VoiceOver and physical-phone evidence remains separate from Chromium emulation.
