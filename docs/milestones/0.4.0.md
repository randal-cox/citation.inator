## Delivered scope

- Shared headless Node/browser analysis and preview API, portable SHA-256 source/context guards, public candidate import entries and JSON CLI. The local server is an optional adapter; the demo uses the shared API in-browser by default. Hosts own document transactions, undo, persistence and publishing.
- Complete editable text/Markdown source with source-derived bibliography records, conservative format detection and manual override, partial reference rules/raw evidence, source-local year letters/reprints and manual identifiers. Matching stays separate from text-span approval and provider identity.
- Bounded native PDF/DOCX/ODT extraction into a text working copy. Original bytes stay available. Office links and opaque managed citation fields are retained in metadata; PDF excluded text remains recoverable. No OCR, native-format round trip or general layout fidelity is claimed.
- Document-first review, immediate radio choices, live Converted Document and separate Reading Preview, source/cache downloads, retained original bibliography and stale-response guards. Unsupported linked/noncontiguous spans stay unchanged with explicit outcomes.
- Automatic browser Crossref/Open Library lookup after selecting a reference, direct known-ID resolution, strict article DOI acceptance, manual book edition choices and offline/manual/identifier-free completion. Source dates/fields remain authored.
- Candidate ranking prioritizes author/work-type evidence; explicit edition/reprint qualifiers are removed from search queries without editing titles. Conflicting/missing supplied metadata remains proposed/red until explicit override. Valid identifier syntax is not identity approval. Distinct records claiming a canonical DOI/ISBN withhold it from all claimants and report a diagnostic, preserving raw entries.
- Separate Looking up/Needs review counts, consistent navigation, complete accordion panels, distant/conflicting results under More results, real-publication examples and optional private local corpus. Private manuscripts/configuration/evidence are excluded from Git and distributions.
- Draggable/resizable review popups with pointer/keyboard controls, text selection preserved, viewport containment and remembered geometry. Configurable JS/JSON limits cover source/files/records/groups/choices, native pages/XML and reference scheduling.
- Usage docs for public candidate Node/browser/native/CLI paths, unchanged-source and metadata boundaries, manual identities and host responsibilities. Notation keyword and reading namespace are configurable and bound to the review context.

## Agreed exclusions and support limits

- Output is reviewed Markdown plus a portable reference cache. Native editing, OCR, full PDF layout reconstruction and arbitrary rich-text source replacement are not promised.
- Initial source matching supports APA/Chicago author-date, numeric brackets and conservative undated forms; this is not recognition of every house style. Unsupported bylines/fields remain raw. Existing stable rendering styles remain available separately.
- Embedded manager metadata is retained opaquely during extraction, not synchronized with Zotero or converted into trusted records automatically. External managers remain 0.6.0.
- Books/ISBNs require an edition decision. Provider result windows are bounded and can omit a valid edition. Provider failure does not imply a work has no identifier. A reviewer can intentionally override a conflict; that action does not certify the citation's scholarly claim.
- The headless API imposes no required host layout or CSS. The current demo is an example host, not a generic mountable editor component. Draft agrees with the headless host boundary; site-cache reuse and host-assigned IDs are implemented; draft accepted allocation in preview.3 and requested the preview.4 short-title fix; translation/i18n is planned soon in 0.5.0.

## Known limits and follow-up

- Linked/noncontiguous/decoded source edits retain accepted-needs-adapter safeguards. The host editor must provide a tested rich-text transaction adapter; source span unions are never blanket replacement permission.
- PDF columns, tables, equations and rotated material need reader review. Headers/footers are only proposed from repeated sequential page-margin evidence; exclusions remain inspectable. Encrypted/unreadable/scanned PDFs require a different extraction/OCR path.
- Complex native structures, auxiliary office parts and images are not fully reconstructed; original files remain the recovery path. Manager field chunks are provenance, not a new manager integration.
- Native Safari, VoiceOver and physical-phone coverage remain separate from actual Chrome and emulation. Static public HTTPS deployment is not yet verified.
- Add comprehensive host-styled live demos, feature-to-example coverage and i18n during 0.5.0, without postponing usage instructions for released APIs.
