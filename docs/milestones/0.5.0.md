# Milestone 0.5.0 — Developer learning and live demos

The maintainer also requested this track on 20 November 2026. Plan a public learning site with a live browser playground, progressive tutorials and heavily annotated examples. Do not limit documentation to an API inventory.

- Start with a minimal page, then explain initialization, notation, formatting styles, CSS/namespaces, panel behavior and accessibility.
- Cover structured records, editions/year letters, access preferences, artwork, evidence, tags, shared bibliographies, editor notes and reviewed import. Each example should connect visible output, source notation and configuration.
- Provide editable examples with reset controls, complete source and downloadable runnable projects for npm and non-npm users.
- Explain unsuccessful cases too: unknown references, ambiguous matches, skipped extraction regions, stale revisions, unavailable providers and offline behavior.
- Include integration recipes for static sites and build pipelines, then a worked draft.inator integration showing explicit review, revision checks and host-owned persistence. The host editor remains a separate project. Initial read-only inspection and compatibility questions are recorded in [the integration boundary](../draft-integration.md).
- Maintain a feature-to-example/documentation matrix so additions cannot quietly lose coverage. Distinguish supported APIs from experiments and identify the library version used by each example.

GitHub Pages can host the static HTML/CSS/JavaScript learning site; see [GitHub's hosting documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Build from the repository using an intentional deployment workflow with correct project-base paths. No deployment is claimed here. Local parsing/compiling and saved provider fixtures should make the main demonstrations usable without a backend or credentials. Live provider lookup is optional and subject to browser CORS/provider constraints; server-side checks, credentials or proxies require separately hosted services. A published demo must never include private manuscripts.


## Status and sequencing

Planned after reviewed import 0.4.0 and before external bibliography-manager integration 0.6.0. The maintainer confirmed this sequence on 21 November 2026. No package version or released artifact is changed by the plan.

0.3.0 and 0.4.0 still include complete usage documentation and examples for their own delivered APIs. This milestone broadens pedagogical coverage across the whole library, rather than postponing basic instructions.

## Delivered

Planning only. The existing local import-review prototype is 0.4.0 development work and is not the comprehensive learning site.

## Acceptance and evidence

A new developer should load the library, compile a citation, configure an inspector and complete a reviewed-import example from a clean download without external assistance. Every feature should have an annotated runnable example and documented support limits. Verify deployed GitHub Pages base paths, keyboard/touch and narrow layouts, offline fixtures and source links. No deployment or developer acceptance is claimed yet.

## Known limits and follow-up

Coordinate the worked editor example with the separate draft.inator project. Keep backend-only behavior distinct from static/browser examples. Follow the agreed 0.5.0 target when a release candidate is ready.
