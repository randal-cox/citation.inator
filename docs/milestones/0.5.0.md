# Milestone 0.5.0 — Developer learning and live demos

**Active, authorized 23 November 2026 after final 0.4.0 adopter sign-off.** The maintainer first requested this track on 20 November 2026. Build a public learning site with a live browser playground, progressive tutorials and annotated examples.

Developers should learn by editing working examples that connect visible output, source notation and configuration. The checklist below is the scope; the linked coverage matrix tracks individual features.

The planned public host is GitHub Pages. Local compiling/parsing and saved provider fixtures keep core demonstrations usable without a backend or credentials. Live provider lookup remains subject to browser/provider constraints. Deployment, translation and clean-download acceptance are not yet claimed.


## Work checklist and sequence

The scope and order are agreed. Start with the coverage inventory and a runnable first citation, then add the editable playground and successive tutorials. Coordinate the worked editor recipe with draft as it becomes concrete. Routine layout and implementation decisions do not need a new scope approval.

- [ ] Progressive quick start: load/init first; compile one citation; add endnotes and the inspector; explain the notation alongside the rendered result.
- [ ] Editable browser playground: source, structured reference data and configuration connected to live output; reset controls and complete examples.
- [ ] Feature tutorials: five styles and their limits, CSS/namespaces, titles/icons, hover/click/panel movement, keyboard/accessibility, formatted references, locators/prefixes, original/reprint years and year letters.
- [ ] Advanced examples: reader access/privacy and services, artwork/media/rights/provenance, evidence/credit, editor notes, tags/filters and shared/cross-page bibliographies.
- [ ] Import walkthrough: paste/text/Markdown/PDF/DOCX/ODT intake, bibliography/source evidence, ambiguous/unmatched decisions, DOI/ISBN proposals and edition choices, local/identifier-free completion, converted Markdown/cache downloads.
- [ ] Runnable downloads: minimal npm and non-npm projects, static-site/build recipes and source links tied to their library version.
- [ ] Worked host/draft integration: host appearance, source revisions, explicit review, undo/transactions and persistence; use the actual accepted 0.4.0 contract.
- [ ] UI translation/i18n: configurable labels, real plural rules, locale-aware values, English fallback and an example translation. Host appearance remains distinct from language; this does not promise exhaustive international citation-manual conformity.
- [ ] Public static learning site: GitHub Pages deployment workflow with correct project-base paths, local compiling/parsing and saved provider fixtures. Verify published assets/links; keep optional live provider behavior visibly distinct from fixture output.
- [ ] Coverage and acceptance: maintain [the feature/example matrix](../learning-coverage.md), teach failures/offline/stale cases, test clean downloads and keyboard/touch/narrow layouts, and run the standard milestone/adversarial procedure.

Version 0.6.0 retains bibliography-manager connections and source maintenance. The separate bibliography-auditor product remains a research revisit. Neither is a prerequisite for the learning site.

The development candidate is `0.5.0-preview.0`; it has not been published. Stable release artifacts remain 0.4.0 and immutable.

## Delivered

Implemented the first learning slice in `learn/`, built through `npm run build:learn` into a public allowlist under `site/`. It includes seven editable lessons, live source/record/JSON configuration, five style presets, three component-scoped appearances, Hover, full reset, load/init code, diagnostics, Markdown/cache downloads and a generated copied-file starter. Editable output is sanitized by the host with DOMPurify; the compiler's trusted-HTML contract is unchanged.

Implemented shared English/Spanish message catalogues and locale helpers, compiler/static labels, inspector controls and access-settings translation. See [the language guide](../i18n.md) for boundaries. Stable release 0.4.0 remains the published baseline. Public deployment and complete tutorial/starter/draft acceptance remain pending.

## Acceptance and evidence

First-slice local verification on 23 November: 305 unit tests pass (including twelve independent translation/escaping tests and cross-style lesson checks). The existing full browser suite passes on Chrome 158.0.8127.88. A dedicated learning browser test passes against a project-subdirectory static host: live style/reset, malformed JSON, malicious HTML removal, click/Escape, Spanish UI, cache download, local-only requests, 390px layout, missing-asset errors and a clean extracted starter served by its included Node server. Desktop and phone screenshots were visually inspected. Further changes require relevant rechecks.

Independent learner/copy review: **first-slice PASS**, including source recheck of activation/namespace synchronization and bootstrap error handling. Translation review: **PASS for the defined UI-language scope**, after trigger/settings-label, numeric and unresolved-fallback fixes; the dedicated browser test verifies generated trigger relabeling and open-settings language changes without losing unsaved selections. These are bounded first-slice reviews, not milestone-wide acceptance.

Two reviewer launches inside the restricted sandbox aborted during macOS Chrome registration and caused crash reports. Browser tests now default to Playwright's dedicated browser, with a system executable only by explicit `CITATION_CHROME`. The learning suite subsequently passed with the separately installed headless shell in a browser-capable execution context. No maintainer Chrome settings were changed.

A new developer should load the library, compile a citation, configure an inspector and complete a reviewed-import example from a clean download without external assistance. Every feature should have an annotated runnable example and documented support limits. Verify deployed GitHub Pages base paths, keyboard/touch and narrow layouts, offline fixtures and source links. No deployment or developer acceptance is claimed yet.
